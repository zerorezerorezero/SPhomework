# 執行緒 (Thread)、競爭條件 (Race Condition)、互斥鎖 (Mutex)、死結 (Deadlock)

## 1. 執行緒 (Thread)

**執行緒**是作業系統能夠進行運算排程的最小單位。一個行程 (Process) 可以包含多個執行緒，這些執行緒共享該行程的資源（如記憶體空間、檔案描述符），但每個執行緒有自己的堆疊 (Stack) 和暫存器狀態。

### 執行緒與行程的差異
| 特性 | 行程 (Process) | 執行緒 (Thread) |
|---|---|---|
| 資源開銷 | 較大（獨立的記憶體空間） | 較小（共享記憶體） |
| 通訊方式 | IPC（行程間通訊） | 直接讀寫共享變數 |
| 建立速度 | 慢 | 快 |
| 隔離性 | 高（彼此獨立） | 低（一個掛掉可能影響全部） |

### Python 中的執行緒
Python 提供 `threading` 模組來建立和管理執行緒。由於 GIL (Global Interpreter Lock) 的限制，CPython 的執行緒在 CPU 密集型任務上無法真正平行執行，但對於 I/O 密集型任務仍然非常有效。

## 2. 競爭條件 (Race Condition)

**競爭條件**是指多個執行緒同時存取共享資源，且最後的結果取決於執行緒執行的時間順序（運氣）。當兩個以上的執行緒同時讀取並寫入同一塊資料時，如果沒有適當的同步機制，就會發生資料不一致的情況。

### 經典範例：存款餘額錯誤
```
初始餘額：1000 元
執行緒 A：讀取餘額 -> 1000
執行緒 B：讀取餘額 -> 1000
執行緒 A：存入 500 -> 計算 1000+500 = 1500
執行緒 B：存入 500 -> 計算 1000+500 = 1500（錯誤！應為 2000）
執行緒 A：寫回 1500
執行緒 B：寫回 1500
最終餘額：1500（短少 500 元）
```

## 3. 互斥鎖 (Mutex)

**互斥鎖 (Mutual Exclusion Lock)** 是最基本的同步機制，用來保護共享資源不被多個執行緒同時存取。

### 運作原理
- `acquire()` / `lock()`：取得鎖。如果鎖已被其他執行緒持有，則阻塞等待
- `release()` / `unlock()`：釋放鎖，讓其他執行緒可以取得

### 使用 Mutex 修正上述問題
```python
lock.acquire()
餘額 = 讀取餘額()
餘額 += 500
寫回餘額(餘額)
lock.release()
```
加上 Mutex 後，同一時間只有一個執行緒能執行「讀取-修改-寫回」的完整操作，保證資料正確。

## 4. 死結 (Deadlock)

**死結**是指兩個以上的執行緒彼此等待對方持有的資源，導致所有執行緒都無法繼續執行的狀態。

### 死結發生的四大條件（Coffman 條件）
1. **互斥 (Mutual Exclusion)**：資源一次只能被一個執行緒使用
2. **持有並等待 (Hold and Wait)**：執行緒持有一個資源的同時，正在等待另一個資源
3. **不可搶佔 (No Preemption)**：資源不能被強制從執行緒手中拿走
4. **循環等待 (Circular Wait)**：存在一組執行緒 {T1, T2, ..., Tn}，T1 等待 T2 持有的資源，T2 等待 T3 持有的資源，...，Tn 等待 T1 持有的資源

### 死結範例：哲學家用餐問題
兩位哲學家各拿一隻筷子，都在等待對方放下筷子，形成循環等待，導致永遠無法用餐。

### 避免死結的方法
- **破壞持有並等待**：一次取得所有需要的資源
- **破壞循環等待**：為資源編號，強制依照順序取得資源
- **使用超時機制**：嘗試取得鎖時設定逾時時間
- **使用較高層級的同步工具**：如 Python 的 `queue.Queue`、`Semaphore` 等

---

## 總結

| 概念 | 說明 | 解決方案 |
|---|---|---|
| **Thread** | 輕量級的執行單元，共享行程資源 | 適度使用，注意同步 |
| **Race Condition** | 多執行緒競爭共享資源導致資料錯誤 | Mutex、Lock 等同步機制 |
| **Mutex** | 保證同一時間只有一個執行緒存取資源 | `threading.Lock` |
| **Deadlock** | 執行緒互相等待導致全部卡住 | 資源排序、一次取得、超時機制 |
